## Central Sensitization Tracker — ONBOARDING

Это краткая инструкция по проекту, чтобы быстро в него погрузиться и использовать как контекст для нейросетей.

---

## 1. Назначение

- **Central Sensitization Tracker (CST)** — статический веб‑дневник симптомов центральной сенситизации.
- Цели:
  - ежедневное заполнение 7 симптомов по шкале 0–10;
  - фиксация лекарств/добавок и заметок;
  - просмотр статистики и графиков по периодам;
  - экспорт данных в Excel;
  - в перспективе — авторизация и роли (пациент/врач, Supabase/PostgreSQL).

---

## 2. Структура проекта

- `index.html`
  - Разметка всего приложения:
    - модалка профиля (`#profileModal`);
    - оверлей календаря (`#calendarOverlay`);
    - шапка и вкладки (`.tabs`: Сегодня / Статистика / Календарь);
    - представление трекера: `#trackerSummary` (сводка) и `#trackerForm` (форма);
    - представление статистики: `#viewStatistics` (карточки + график + Excel).
  - Подключение скриптов (в конце `<body>`):
    - SheetJS (`xlsx.full.min.js`) для Excel;
    - `storage.js` (слой хранения);
    - `app.js` (бизнес‑логика).

- `styles.css`
  - CSS‑переменные (`:root`):
    - базовая палитра: `--primary`, `--secondary`, семантические цвета `--success`, `--warning`, `--danger`;
    - цвета симптомов: `--symptom-*` (pain, fatigue, …);
    - шкала тяжести: `--severity-low/medium/high`.
  - Компоненты:
    - шапка, вкладки, карточки, модалки, тосты;
    - календарь (сеткой), слайдеры, quick‑кнопки;
    - сводка дня (`.summary-*`);
    - карточки статистики (`.stat-*`) и линейный график (`.chart-*`).

- `app.js`
  - Глобальный `state`:
    - `currentDate`, `selectedDate`, `currentView` (`tracker`/`statistics`);
    - `currentRange` (`week`, `month`, `3months`, `custom`), `customFrom`, `customTo`;
    - `data` — записи по датам (ключ `YYYY-MM-DD`);
    - `profile` — профиль пациента;
    - `chartFilter` — какой симптом показывать (или `all`);
    - `chartCompare` — режим сравнения (`off`, `day`, `week`, `month`, `period`);
    - `trackerEditMode` — флаг «в режиме редактирования формы».
  - Константы:
    - `SYMPTOMS` — ключи симптомов;
    - `COLORS`, `LABELS`, `ICONS`, `EMOJIS`, `DESCS` — маппинги для рендеринга и описаний.
  - Подсистемы:
    - работа с датами и календарём (рендер сетки, запрет будущих дат);
    - трекер (слайдеры, quick‑кнопки, автосохранение, сводка vs форма);
    - счётчик дней без записи;
    - профиль пациента;
    - статистика (карточки симптомов, тренды);
    - SVG‑график;
    - экспорт в Excel.

- `storage.js`
  - Обёртка над `localStorage`:
    - ключи `cst_data` (все записи симптомов), `cst_profile` (профиль пациента);
  - API:
    - `loadEntries()`, `saveEntries(data)`;
    - `loadProfile()`, `saveProfile(profile)`.

## 3. Модель данных

### 3.1. Симптомы

`SYMPTOMS = ['pain','fatigue','sleep','cognitive','sensory','digestive','emotional']`

Каждый симптом — целое от 0 до 10.

### 3.2. Запись по дате

Ключ в `state.data` и `cst_data` — строка `YYYY-MM-DD`:

```js
{
  pain: 0..10,
  fatigue: 0..10,
  sleep: 0..10,
  cognitive: 0..10,
  sensory: 0..10,
  digestive: 0..10,
  emotional: 0..10,
  notes: string,   // заметки
  meds: string,    // лекарства/добавки
  saved: true|false,
  ts: ISOString    // время последнего изменения
}
```

### 3.3. Профиль пациента

```js
{
  name: string,
  gender: 'male' | 'female' | 'other' | '',
  age: string
}
```

`state.profile` и `cst_profile` в `localStorage` синхронизированы через `storage.js`.

## 4. Основные сценарии

### Пациент

1. Открывает приложение — по умолчанию сегодняшняя дата.
2. Если за день уже есть запись:
   - показывается сводка (`#trackerSummary`) с суммой симптомов, значения по каждому симптому, лекарства и заметки.
   - можно нажать «Редактировать» и вернуться к форме (`#trackerForm`).
3. Если записи нет — показывается форма слайдеров и полей.
4. Кнопки:
   - **Копировать с вчера** — переносит значения симптомов/полей с предыдущего дня;
   - **Сбросить симптомы** — ставит все симптомы в 0;
   - **Сохранить запись** — помечает запись как `saved: true`.

### Статистика

1. Вкладка **«Статистика»**:
   - выбор периода: неделя / месяц / 3 месяца / произвольный диапазон дат;
   - Excel‑кнопка для выгрузки.
2. Блок **карточек симптомов**:
   - на каждой карточке:
     - иконка симптома, название;
     - тренд (в процентах);
     - **суммарный балл** по симптомам за выбранный период;
     - подпись: количество дней с данными и краткое описание симптома.
3. **График**:
   - фильтр по симптому (или все сразу);
   - режим сравнения: день к дню, неделя к неделе, месяц к месяцу, период к периоду;
   - линии и точки на SVG.

### Профиль

- Модалка профиля открывается по клику на панель пациента.
- Сохраняется в `localStorage` и используется в заголовке и Excel‑инфо.

## 5. Ключевые функции (опорные точки для ИИ)

### Работа с датами

- `getToday()` — сегодняшняя дата с нулевым временем.
- `startOfDay(d)` — нормализация произвольной даты к полуночи.
- `dateKey(d)` — `YYYY-MM-DD` для индексирования в `state.data`.
- `formatDateInput(d)` — формат под `<input type="date">`.
- `isSameDay(a, b)`, `isAfterToday(date)` — сравнения для календаря и навигации.

### Состояние и записи

- `hasRecord(entry)` — важно: что считается «заполненной» записью (любой ненулевой симптом или непустые notes/meds, либо `saved: true`).
- `readFormEntry()` — считывает текущее состояние формы в объект записи.
- `persistFormToState(markSaved)`:
  - автосохранение черновика при вводе;
  - удаление пустых черновиков;
  - не трогает уже сохранённые (`saved: true`), если `markSaved === false`.
- `saveData()` — явное сохранение и установка `saved: true`.
- `loadDataToForm()` — заполнение UI из `state.data` по выбранной дате.

### Навигация по датам

- `shiftDate(delta)` — переход на соседний день (вчера/завтра), запрет будущих дат.
- `renderCalendar()`, `dayHtml()` — отрисовка календаря с точками‑индикаторами по симптомам.
- `selectDate(key)`, `goTodayCal()` — синхронизация календаря и трекера.
- `countDaysWithoutRecord()` + `updateDaysCounter()` — блок «дней без записи».

### Сводка vs форма

- `trackerEditMode`:
  - `false` и запись есть → показываем сводку;
  - `true` → показываем форму.
- `updateTrackerView()` — переключение между `#trackerSummary` и `#trackerForm`.
- `renderDaySummary(entry)` — сводка по дню:
  - сумма баллов по всем симптомам (0–70);
  - индивидуальные значения и полоски;
  - лекарства и заметки.

### Профиль

- `loadProfile()`, `saveProfile()` — взаимодействие со `storage.js`.
- `updateProfileDisplay()` — обновление аватара и подписи в шапке.

### Статистика, тренды, график

- `getDatesForStats()` — выбор дат диапазона.
- `calcEntrySum(entry)` — сумма по всем симптомам за день.
- `calcTrend(sym, dates)`:
  - считает процентное изменение суммы симптома между первой и второй половиной периода;
  - рост ≥30% → «сильный» тренд с красным бейджем.
- `renderStats()`:
  - собирает список значений симптомов;
  - суммирует; рендерит карточки;
  - вызывает `renderLineChart()`.
- `renderLineChart()`:
  - строит SVG‑график, учитывая `chartFilter` и `chartCompare`;
  - показывает точки только на днях с данными (`hasRecord`).

### Excel

- `getExportRowsForPeriod()` — собирает список `{ date, entry }` за период.
- `exportToExcel()`:
  - Лист «Все симптомы»: дата, значения по всем симптомам, **сумма**, meds, notes, saved.
  - Лист «Сводка»: для каждого симптома — сумма, минимум, максимум, дней с данными.
  - Листы по каждому симптому.
  - Лист «Инфо»: период, дата выгрузки, короткая информация о пациенте.

## 6. Расширение и модификации

### Добавить новый симптом

1. Обновить константы в `app.js`:
   - добавить ключ в `SYMPTOMS`;
   - добавить цвет в `COLORS`, подпись в `LABELS`, иконку в `ICONS`, emoji и описание в `EMOJIS`, `DESCS`.
2. Добавить HTML‑блок `.symptom-cat` в `index.html`.
3. Добавить `.cat-*` и `.icon-*` в `styles.css`.
4. Убедиться, что график, статистика и Excel автоматически учитывают новый симптом (используют `SYMPTOMS`).

### Перенос хранения в БД

1. Заменить реализацию `storage.js` на запросы к API/БД (Supabase, backend и т.п.).
2. Сохранить подписи методов: `loadEntries/saveEntries`, `loadProfile/saveProfile`.
3. Добавить авторизацию; связать `state.data` с текущим пользователем.

### Авторизация и роли (не реализовано, но заложено в дизайн)

- Запланирован переход к моделям:
  - **пациент** — вводит и просматривает только свои данные;
  - **врач** — видит список своих пациентов и их статистику.
- Рекомендуется использовать PostgreSQL с RLS (например Supabase) и таблицы:
  - `profiles`, `symptom_entries`, `care_links`.

## 7. Рекомендации для нейросетей

- Сохранять архитектуру: чистый HTML/CSS/JS, без сборщиков и фреймворков, пока пользователь не попросит обратного.
- При изменении логики метрик:
  - обновлять `calcEntrySum`, `renderDaySummary`, `renderStats`, `calcTrend` и `exportToExcel` согласованно;
  - явно менять подписи в UI (например «Сумма» vs «Среднее»).
- Любые изменения в симптомах проводить через все связи: `SYMPTOMS`, `COLORS`, `LABELS`, `ICONS`, `EMOJIS`, `DESCS`, HTML и CSS.
- Не использовать иконки Font Awesome Pro; пищеварение — `fa-bowl-food`.
